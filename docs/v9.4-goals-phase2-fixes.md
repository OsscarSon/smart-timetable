# v9.4.0 · Goals Phase 2 修复与补强

## 修复（优先级最高）：日程与 goals-links 现在是一个整体
**问题**：`commit()` 先写日程、再单独写 `goals-links`。关联表写失败时函数仍返回成功（只带 `linksOk:false`），结果课表里有活动，Goals 却不知道它属于哪个目标。

**现在的顺序**（`js/goals-plan.js` · `commit()`）：
1. 先算出每个时段的周 / 星期 / 标题，生成新的关联表。
2. **先写关联表并读回校验**。失败 → 零写入，提示“没能把这些时段和目标关联起来，所以什么都没有添加”，预览保持打开。
3. 再写日程并读回校验。失败 → 回滚日程，并把关联表**还原为写入前的原文**。
4. 两者都成功才弹出撤销提示。`linksOk:false` 的“半成功”状态不再存在。

## 补强（原 Phase 2 备注里的第 3 点）
- **认出被移动的时段**：用户自己拖动了 Goals 排的活动后，若能确定对应关系（同一周、同标题、同时长、未被别的关联占用），目标页会提示“N 个时段被你移动过”，并提供「跟随 N 个已移动的时段」——只更新关联表，不动日程。
- **一键重新排**：有被移动 / 被删除的时段时，主按钮变成「重新排剩余时间」（引擎本来就只补未覆盖的部分，不会重复排）。
- **目标级撤销**：「移除 N 个未到的时段」——只移除这个目标仍在原位、尚未发生、没打勾的时段；先拍 Undo 快照、读回校验，失败则回滚；移除后可立即撤销。
- 不确定的情况（删除、整批被撤销）不会被当成“被移动”。

## 不变
- **Goals 仍然不跨设备同步**（刻意保护旧系统，等冲突处理完善后再开）。
- 「已排程」仍不等于「已完成」。
- 不在 Phase 3 里夹带这些改动。
