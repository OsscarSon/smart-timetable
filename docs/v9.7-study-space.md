# v9.7.0 · Study Space 学习工作台（Phase 3A + 3B）＋ Goals 同步回归测试

## 一、Goals 跨设备同步：补充的两组回归测试（没有改同步实现）
新增 `tests/goals-sync-regress.cjs`（25 项，两个独立浏览器环境 + 假云端，可让每台设备单独“离线”）。

**场景 1：A 移除 / 删除，B 持有旧关联后重新同步 → 不会错误恢复有效关联**
- 1a A「移除未到的时段」，B 只是拿旧数据重新同步：B 的时段消失、有效关联 0；A 再同步也不会被 B 的旧数据盖回去。
- 1b B 离线时自己也改了 `goals-links`（给另一周加了排程），A 同时移除了旧时段并另排了一个新的：两边的关联表按条合并，被移除的 5 个旧关联会“回到表里”（并集合并的预期行为），但因为课表里已经没有对应活动，**全部判为失效**；最终两边都只剩各自新排的 2 个有效关联，课表一致，没有弹窗。
- 1c A 删除整个目标：B 同步后目标消失，不会被旧关联“复活”；已排进课表的活动沿用现有语义（保留），两边一致。

**场景 2：A、B 离线修改同一周的不同日程（A 新增一个个人活动；B 挪动一个目标时段并删除另一个）**
- 冲突处理：`mochi-wk:*` 仍是整块“最后修改的赢”，B 上线时弹出**一次**通用冲突提示，并点名“11/16 那一周的安排”；A 不弹。
- 选“用云端”：B 的挪动 / 删除被取代，A 的新增保留；5 条关联全部重新有效，没有幽灵关联，也不误报“需要重新排程”。
- 选“保留本机”：A 同步后得到 B 的版本（A 的新增丢失，这是该选项写明的代价）；只剩 3 条有效关联，被挪走的 1 条识别为“被移动”，被删的 1 条识别为“已消失”，没有被当成已排程。
- 恢复路径：A「跟随移动」→ 有效关联 4，B 同步后也是 4；B 走真实界面“重新排剩余时间”只补缺口（需要 40 分钟），提交后 A = B，有效关联数 = 课表里的目标时段数。

**反向验证**：把 `mergeLinks()` 禁用 → 3 项失败；让 `validLinks()` 不检查活动是否仍在原位 → 多项失败。恢复后全部通过。

**结论**：这两组场景下现有同步实现的行为符合预期，不需要改动。已知限制不变：同一周日程仍是整块“最后修改的赢”（由用户在冲突提示里选）；失效的旧关联会留在关联表里直到下次排程提交时被清理（上限 3000 条）。

## 二、Study Space
### 入口与导航
- 底部“学习”标签：**从别的页面点进来 → 学习工作台**；已经在学习分组里（作业 / 复习计划）再点，留在原处。
- 学习分组顶部是三个子标签：🏠 工作台 ｜ 📝 作业 ｜ 📚 复习计划。作业和复习计划页面及功能完全不变；日视图的作业条、搜索跳转作业等直接 `showView('hw')` 的入口也不变。
- 没有新增顶层路由；`ss` 只是学习分组（`GRP.ss='hw'`）里的又一个视图。科目详情 / 复习队列是工作台里的内部状态。

### 工作台（3A）
欢迎横幅（Buddy 用 `assets/buddy/happy.svg` / `idle.svg`）· 三个统计（待复习 / 作业到期 / 今天未完成的学习时段）· 即将到来 · 本周学习进度 · 最近的考试倒计时 · 科目卡片 · 复习队列总览。完全没有数据时显示带下一步按钮的空状态，而不是 0/0/0。

### 科目详情（3B）
- **章节**：评分按钮（忘了 / 模糊 / 记得）调用现有 `srsRate()` + `sv()`；添加章节写入 `ST.topics`（和复习计划页同样的 `{s,n,iv:0,nx}`）。
- **作业**：“新作业 / 点作业修改”打开原来的编辑框（`openHw()`，科目预填），勾选完成走 `hwSave()`。
- **考试与目标**：考试日写 `ST.ex` + `sv()`；关联的目标只读，点击打开原 Goals 页面。

### 数据口径
| 显示 | 来源 / 定义 |
|---|---|
| 待复习 | `ST.topics` 中 `iv>0 且 nx<=今天`（与 study.js 一致；没学过的不算复习，nx 缺失不算到期） |
| 作业到期 | 未完成且逾期或今天到期（与 `hwDue()` 的 over+today 一致） |
| 学习时段 | 当前课表里 `a:1`（一键排程生成）的活动，加上 Goals 排程关联仍然有效的活动；是否完成**只看课表里的打勾**（`DN`），不看时长 |
| 即将到来顺序 | 逾期作业 > 今天作业 > 到期复习 > 最近的学习时段 >（3 天内到期的作业）；同级按日期 / 标题 / id，输入顺序不影响结果 |
| 科目卡进度 | “已开始的章节 / 全部章节”（至少评过一次）。**不是**“学习掌握度 %” |
| 科目卡范围 | `ST.subs` + 有章节 / 作业 / 考试日的科目；只在课表里出现过的课（没有任何学习数据）不占卡片 |
| 作业科目匹配 | `hw.js` 保存时把科目标签截到 12 字（先 trim 再截，可能带尾随空格）；超长科目名的作业会归到同名长科目下 |
| 目标关联 | Goals 没有“科目”字段，所以按**步骤标题 = 科目名**（忽略大小写）关联；只显示 study 空间、未归档、未删除的目标 |

### 目标显示开关
设置 → **Study Space** → “在学习空间显示目标”。存在本机 `studyspace-prefs`（`{"goals":false}`），默认开；**不是** `mochi-*` 键，不参与云同步，也不进备份。关闭只影响 Study Space 的显示，不改 Goals 数据 / 排程 / 同步。

### 写入边界（`npm run check` 强制）
- `study-space-core.js` 是纯函数：不能出现 `document` / 存储 / `sv(` / `hwSave` / `srsRate` / 云同步 / Undo。
- `study-space.js`：不能出现任何 `mochi-*` / `goals-*` 键字面量；本机存储只允许 `studyspace-prefs`；不能碰云同步 / Undo / 课表保存 / Goals 写入（`saveGoal`、`GoalsPlan.commit` 等）。
- 文案三种语言键必须一致，用到的键必须有译文；CSS 选择器必须以 `.study-space-` 开头（外层 `#v-ss` 例外）。

### 对原有文件的改动
`index.html`（样式 / 脚本引用、`#v-ss`、设置里的开关）· `js/app.js`（视图注册、子标签、标签落点）· `js/menu.js`（设置分类加一行）· `sw.js`（预缓存 + 缓存名）· `scripts/check.mjs` · `js/version.js` / `package.json`。`study.js`、`hw.js`、`srs.js`、`goals*.js`、`sync.js`、`hook.js` **没有改动**；Study Space 通过“包装” `rHw` / `rSt` / `showView` 在数据变化后刷新自己。

### 副作用（有意为之，只在用户主动操作时发生）
在 Study Space 里给**不在 `ST.subs` 的科目**添加章节或设考试日，会像复习计划页的“+科目”一样把它加入 `ST.subs`，否则旧页面和一键排程看不到这些数据。
