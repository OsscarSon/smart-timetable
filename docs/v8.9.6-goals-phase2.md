# v8.9.6 · Goals Phase 2：把已确认的步骤匹配到现有空档

> 范围严格按 `PHASED_PROMPTS.md` 的 Phase 2：**只把“已确认的 Goal 步骤”匹配到现有空档**，支持真实约束、不可行性提示、预览勾选、确认与撤销；不绕过原有的 AI / 日程保护逻辑。

## 用户看到什么
1. 打开一个已保存的目标 → 编辑页底部多了「Time slots / 时间安排」：显示已排好的时长与下一个时段，和「Find time slots / 寻找空档」按钮（未保存的修改、暂停 / 完成 / 归档的目标会禁用并说明原因）。
2. 点按钮进入**排程预览**：汇总（需要 / 已排 / 范围内空闲 / 预计完成 / 冲突）、每个步骤是否排得下、按天列出的时段（逐个勾选）、可展开当天原有的课程 / 活动（叠加预览）。
3. 点「Add N selected sessions」才会写入。弹出可撤销提示；点撤销会逐字节还原。
4. 取消 / ‹ / Esc / 底部 Cancel = **零写入**（测试里逐键比对 localStorage）。

## 排程规则（`js/goals-plan.js` 的 `plan()`，纯函数）
- **只读现有日程**：`Sched.dayItems` = 手动活动 + 重复活动 + 固定课程；这些永远不会被移动或覆盖。隐藏的列（如周末）不排；只用课表的显示范围（H0–H1）；今天只排“现在”之后。
- **约束**：每日上限、单次时长、休息缓冲（目标自己的时段前后各留 N 分钟）。每科拆成**大小相近**的几块（例如 240 分钟 → 6 × 40），不会出现 45+45+…+15 的零头；任何 < 25 分钟的块只可能是该步骤的最后一小截（有随机测试守着）。
- **最晚日**：步骤截止日、目标截止日、希望完成日取最早者；学习空间在考试 / 截止日**前一天**结束（预览顶部有提示）。没设截止日则排接下来 14 天；最多看 180 天。
- **顺序**：依赖在前，其余按最晚日 → 原顺序；循环依赖会被忽略并提示。
- **节奏**：「平均分散」（按“块”均匀铺开，默认）/「尽早排完」。估时有区间时可选按“区间上限”（默认，更保守）或“预计时间”。
- **不重复排程**：已存在、仍有效、还没发生的关联时段会算作“已覆盖”，只补剩下的。
- **不够排时如实报告**（短缺分钟数 + 原因：没日子 / 没空闲 / 空闲用完 / 前置步骤排不下），**从不超排**；并试算建议：“每天最多允许 X”、“改用最终截止日”、“减少预估时间”。建议只是重新预览，不会自动应用。

## 写入路径（唯一的日程写入口 `commit()`）
1. 校验目标未变（`rev` 一致，否则拒绝并零写入）。
2. 对着**此刻**的日程复核每个已勾选时段（预览之后可能变了）：已过去 / 隐藏日 / 超出范围 / 与新出现的活动冲突 / 选中项互相重叠 → 跳过并告知，其余照常写入。
3. `Undo.snap()` → 与 `agent.js` 相同的 `WK[w].push` + `saveWeek` → **读回校验**（`put2` 会吞掉配额错误，所以这里自己读回比对；不一致则回滚内存并报错，什么都没改）。
4. 写 `goals-links`（独立关联表，**不给原活动加字段**）；草稿目标自动变“进行中”；`Undo.toast`。
5. 写入的是普通手动活动，**不带 `a:1`**，所以「学习」页自动排程不会误删；「问问 Mochi」把它们当手动活动处理（固定课 / 重复活动仍然只读）。

## 关联与失效检测
`goals-links` 记录 `goalId / stepId / 课表 id / 周 / 星期 / 起止 / 标题`。读取时核对活动是否仍在原位、原样：被删、被移动、被撤销的都算失效，不再算“已排程”（用户自己移动过的活动**不会被 Goals 删除或再动**）。同一位置只认最新一条（测试抓到过“撤销后重排出同一位置，旧记录复活”导致已排分钟重复计算，已修）。`goals-links` 不带 `mochi-` 前缀，不进云同步。

## 边界（`scripts/check.mjs` 自动守着）
`goals-plan.js` 不得出现任何 `mochi-*` 键字面量；不得碰云同步 / 日历插件 / 固定课程 / 重复活动 / 作业 / Study 排程；写日程前必须 `Undo.snap()` / `Undo.toast()`；所有文案键三语齐全。`goals.js`（Phase 1）仍然没有任何写入逻辑，只挂了 3 个入口。

## 可关闭 / 可回滚
- 单独开关：`GoalsPlan.setEnabled(false)`（键 `goals-plan-prefs`）→ 编辑页没有入口、卡片不显示“已排”，Phase 1 草稿功能照常，`goals-links` 原样保留；`setEnabled(true)` 恢复。
- 整个 Goals：`Goals.setEnabled(false)`（Phase 1 已有）。
- 代码回滚：删掉 `index.html` 里的 `goals-plan.js`、`sw.js` 里的 `'goals-plan'`，`goals.js` 里的 `root.GoalsPlan &&` 守卫会让一切退回 Phase 1。

## 没做 / 没验证的（请知悉）
- **只在 Chromium 里测过**；没在真机、Android WebView、Safari、离线（Service Worker）下测。
- 目前**不会**根据“某个已排时段被勾选完成”自动给步骤加完成进度（“已排程 ≠ 已完成”，完成度仍只来自步骤上的手动勾选）。
- 没有“重新排程时替换旧的未来时段”和“一键撤回某目标已排时段”的界面（要改请直接在时间表里删，失效检测会自动跟上）。
- 薄弱科目加权、学习 / 工作 / 生活空间各自的专属规则、Buddy 的排程微交互：不在 Phase 2 范围。
- 预览里的“原时间表叠加”是按天展开的列表，不是画在周视图上。
- 写入的时段标题是步骤标题（最多 24 个字符），不带目标名。
