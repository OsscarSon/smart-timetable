# v9.6.0 · Goals 排程跨设备（任意设备都能管排程）

v9.5 只同步了目标本体，排程时段只能由排程的那台设备管理。v9.6 把排程关联表 `goals-links` 也同步了，并且**按条合并**，所以任何设备都能排程、跟随移动、移除未到的时段。

## 改了什么
- **`goals-links` 参与云同步**（`js/hook.js`、`js/sync.js` 的 `syncKey()`）。设备 id（`goals-meta`）和偏好（`goals-prefs` / `goals-plan-prefs`）仍只在本机。
- **按条合并**（`sync.js` 的 `mergeLinks()`）：两台设备都改过关联表时，按每条关联的 `id` 取并集；同一 `id` 取 `u`（最后修改时间）较新的。关联是“活动位置 + 目标 + 步骤”的记录，读取时本来就会检查对应活动是否还在原位，所以合并后“复活”的旧记录（活动已被删 / 移动）会自动判为失效，不会被当成已排程。
- **先拉后推**：目标 / 关联表有未上传的改动时，防抖上传改走“先同步（拉取→合并）再上传”，避免把别的设备刚写的内容整块盖掉。普通数据的上传方式不变。
- **拆掉 v9.5 的限制**：不再有“已在另一台设备上排程”的只读状态、接管按钮和 `errElsewhere`；`planDevice` 字段只保留不用（旧版本写过的值原样保留）。
- 新增/修改的关联带 `u` 时间戳（提交排程、跟随移动时写入）。

## 行为
- 在手机上排好，电脑上能看到“Scheduled…”，再点“寻找空档”不会重复排；两边都可以跟随移动、重新排、移除未到的时段。
- 两台设备各自、同时给不同的周加排程：关联表合并，两边都保留。

## 已知限制
- **同一周的日程数据（`mochi-wk:*`）仍是整块“最后修改的赢”**。两台设备在同步前，给**同一周**都加了排程 → 会出现通用的冲突提示，选一边后另一边那周的新增时段会丢（对应的关联会自动失效，可用“重新排剩余时间”补上）。不同周互不影响。
- 关联表上限 3000 条（超出时保留最新的）。
- 同一目标两边同时编辑，输的一边的改动被覆盖（没有字段级合并）。

## 测试
`tests/goals-sync-smoke.cjs`（17 项，两个独立浏览器环境 + 假云端）。新增：关联表上云、A 认得 B 排的时段、A 再排不重复、两台同时各加一个排程后合并一致、A 移动并跟随后 B 也认得、B 移除未到的时段（含 A 排的）后 A 的课表同步清空。
**反向验证**：临时禁用 `mergeLinks()` 后，其中 3 项会失败；恢复后全部通过。
