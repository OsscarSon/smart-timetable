# v8.5 改动说明

1. 底栏：作业 + 学习 合并成「学习」（顶部分段：作业｜复习计划）；新增「健康」（运动｜美容｜饮食）。运动计划原来在「更多」里，现在属于健康栏。
2. `js/health.js`：美容护肤打卡（早 / 晚步骤，连续打卡天数）、饮食（按餐记录热量、饮水杯数、每日目标）。数据 key：`mochi-bt`、`mochi-di`，自动云同步。
3. 食物热量用开源数据库 Open Food Facts（浏览器直接查，免 key）；查不到可手动输入。
4. AI 读取：`healthSummary()` 会放进整周重排（`log.js` → `api/plan.js` 规则 13）和「问问 Mochi」快照（`sched.js` → `api/agent.js`）。AI 只读、不改健康数据。
5. 字典：`js/lang-health.js`（英 / 马来文）。

未验证：真机上的手感；Open Food Facts 在 App WebView 里的跨域请求。
6. 拖拽排序（SortableJS）：学习科目、护肤步骤、运动卡片、科目库。手机上按住约 0.2 秒再拖。
7. 多模型后端：`api/_llm.js`。一句话添加、整周重排、问问 Mochi 这三类文字请求按 `LLM_ORDER` 依次尝试 Groq → Cerebras → Mistral → Gemini（没填 key 的跳过，一家 429 / 出错就换下一家）。拍照识别和用户自带的 key 只走 Gemini。
   部署：Vercel 环境变量加 `GROQ_API_KEY` 等（见 `.env.example`），只填 Gemini 也照常工作。
   未验证：各家默认模型名（可能已更换）和 JSON 输出的稳定性；小模型偶尔会输出不合格的 JSON，后端会返回错误，前端再走本机 AI 兜底。
8. 本机 AI：默认「智能」（一句话添加用本机，整周重排云端优先）；设置里可改成「云端优先 / 全部优先本机」。引擎顺序：电脑 Ollama → Gemini Nano → WebLLM；手机 Nano → WebLLM；某个引擎出错或 JSON 不合格就换下一个。设置 → 账号与云同步里有「检查本机 AI / 下载 WebLLM / 测试」。
   Ollama：需先安装并运行，并设置环境变量 OLLAMA_ORIGINS 放行本站网址（如 https://你的站.vercel.app）；Safari 不允许 https 页面访问 http://localhost。
   没有做 MediaPipe：它在 Web 上同样依赖 WebGPU，官方已标为“只维护”，模型要自己托管（几 GB），收益远小于成本。
9. WebLLM 自动预下载：打开后约 12 秒、浏览器空闲时，在 Wi-Fi 下后台下载（跳过：没有 WebGPU、已有 Nano、省流量 / 蜂窝网络、剩余空间不足 2.5GB、选了“云端优先”或填了自己的 key）。下载完卸载引擎释放显存，缓存保留。设置里可关闭。需要用时若还没下载，直接开始下载，不再弹窗询问。
