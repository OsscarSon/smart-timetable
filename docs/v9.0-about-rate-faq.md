# v9.0 · 版本号修正 + 给 Mochi 评分 + 常见问题与帮助

接在 v8.9.11 之后。

## 1. 版本号：以前菜单底部一直显示 v8.8.1
- 原因：`js/menu.js` 里把 `Mochi Schedule · v8.8.1` 直接写死了，后面每次升级（8.8.2 → 8.9.11）都只改了 `package.json` 和 `sw.js`，没人改这一行，所以菜单永远是 v8.8.1。
- 现在：新增 `js/version.js`，只有一个 `window.MOCHI_VERSION = '9.0.0'`。菜单底部、「更多」页底部、常见问题页、评分提交（`p_version`）都读它。
- 以后发新版要同步三处：`js/version.js`、`package.json`、`sw.js` 的 `VER`（`mochi-v9-0-0`）。`npm run check` 会检查它们是否一致，也会拦住任何文件里再写死版本号。
- **Android 例外**：打包出来的手机 App，系统“应用信息”里的版本是 `android/app/build.gradle` 的 `versionName` / `versionCode`，Capacitor 不会读 `package.json`，每次发布要手动改。

## 3. 给 Mochi 评分（`js/rate.js`）
- 5 颗星（点一颗亮到那颗，有文字提示：很失望 … 太棒了！）+ 提交 / 更新按钮。
- 星星下面是「大家的评分」：平均分、星星填充、总人数、1–5 星分布条。
- 一台设备一票，重新评分 = 更新原来那一票。
- 没配置云端 / 没联网 / 函数还没建：评分先存本机并提示“联网后再打开这里会补发”，统计区显示「暂时看不到统计」+ 重试，不会报错。
- 本机只写 `app-rate`、`app-rate-id`、`app-rate-stats`，**故意不用 `mochi-` 开头**，所以不会进云同步，也不会混进备份文件。
- 文字三种语言内置（zh / en / ms），不走词典。

### ⚠️ 必须做一步：在 Supabase 运行 `supabase/ratings.sql`
Supabase 控制台 → SQL Editor → 把 `supabase/ratings.sql` 整段贴进去运行（可重复运行）。它建一张锁死的表 `app_ratings`（前端不能直接读写）和两个函数：`rating_stats()`（任何人可读统计）、`submit_rating()`（每设备一票）。不运行的话，评分页能打开、能点，但统计区会一直显示“暂时看不到”。
局限：设备 ID 存在本机，清除数据后可以再投一票。这是轻量统计，不是防刷票系统。
