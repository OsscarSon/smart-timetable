## 审计结论（动手前读过的代码）
- `js/health.js`：`BT`（`mochi-bt`，`{am,pm,log:{日期:{am:[序号],pm:[序号]}}}`）和 `DI`（`mochi-di`，`{kcal,water,days:{日期:{w,m:[{t,n,k}]}}}`）。写入函数 `btSave()` / `diSave()`，旧页面刷新 `rBt()` / `rDi()`。**餐别 `t` 存的是中文原文**（早餐/午餐/晚餐/加餐），新界面沿用，只在显示时翻译。
- `js/sport.js`：`SP`（`mochi-sp`）是“运动 + 现在成绩 + 目标成绩”，**不是**每周训练记录；写入 `ssv()`，新增 `addSp()`，刷新 `rSp()`。真正“本周训练”是课表里 `a:2` 的活动，是否完成存在 `DN`（和课表页 / 旧运动页的清单是同一份）。
- `js/study-space.js`、`js/spaces.js`：参考其“只读聚合 + 包装 `showView` / 旧渲染函数”的做法；**没有修改**。
- `js/app.js`：健康分组 = `sp` / `bt` / `di`；底部“健康”落到 `LAST.sp`。
- 预览里的数据（“Recovery 1 rest day”、固定的 3 次训练、演示用热量）在真实数据里不存在，**没有实现**，避免编造数字。

## 每个动作对应的现有函数
| 动作 | 写入路径 |
|---|---|
| 喝水 +1 / −1 / 点杯子 | `dayDi(hDay(0)).w`（上限 30）→ `diSave()` → `rDi()` |
| 护肤打卡 | `BT.log[今天][am|pm]` → `btSave()` → `rBt()` |
| 加护肤步骤 | `BT[am|pm].push(≤12 字)` → `btSave()` → `rBt()` |
| 删护肤步骤 | 同旧页面，但**今天的打卡按位置顺延**（旧页面会把今天的早晚打卡都清空） |
| 记录一餐 | `dayDi(今天).m.push({t,n,k})`，规则同旧页面（名称 ≤30 字，0–5000 kcal）→ `diSave()` → `rDi()` |
| 食物搜索 | 与旧页面同一个 Open Food Facts 请求（8 秒超时、克数自动换算热量） |
| 每日目标 | `DI.kcal` 限制 500–6000，`DI.water` 限制 1–30，空值回到 2000 / 8（同旧页面） |
| 加运动计划 | `addSp(name)`（`ssv()` + `rSp()`） |
| 每周次数 / 删除计划 | `SP[i].w` / `SP.splice` → `ssv()` → `rSp()`（删除前有确认） |
| 训练打勾 | `DN[kk(x,thisW)]` → `put2(K_DN,DN)` → `draw()` / `rf()`，与课表页、旧运动页清单同一条路径 |
| 成绩 / 目标 / 一键排课 | 不重复实现，进入旧运动页（“打开运动计划”） |

## 数据口径
- 总览：饮水 = 今天 `DI`；护肤 = 今天已勾 / 全部步骤；运动 = 本周 `a:2` 时段的已勾 / 总数（没有就显示 –）；“接下来”只列真正没做完的事。
- 本周训练只统计 `a:2`（旧运动页一键排程生成的）。用户手动加到课表里的普通活动不算训练。
- “还差多少”沿用 `sport.js` 的算法（`m:ss` 当分:秒，`h:mm:ss` 当时:分:秒）。
- 最近 7 天：有记录的那天圆点亮起，不统计“达成率”。

## `npm run check` 新增的边界
聚合层必须是纯函数；界面层不能出现 `mochi-*` / `goals-*` 键字面量、不能直接用 `localStorage`、不碰云同步 / Undo / 课表结构 / Goals；`put2(` 只允许 `put2(K_DN, DN)`；`fetch(` 只允许 Open Food Facts；三语键一致且无空值；CSS 选择器必须带命名空间。

## 手动检查清单
1. 底部点“健康”→ 进入健康空间；切到 运动 / 美容 / 饮食 分段按钮的旧页面再点“🌿 健康空间”能回来。
2. 总览数字与旧页面一致；点“+1”后，旧饮食页和 Life Space 的饮水同步变化。
3. 食物搜索（需联网）：搜索 → 点结果 → 改克数 → 记录；旧饮食页能看到同一条。
4. 护肤：勾选 / 加 / 删步骤，旧美容页同步。
5. 运动：加计划、改每周次数、勾选本周训练；课表页对应活动被勾上。
6. 设置里切换 English / 中文 / Bahasa Melayu，新界面文案随之切换。
7. 320px 宽、深色模式、键盘（Tab、←/→/Home/End 切换标签）、刷新后数据仍在。
