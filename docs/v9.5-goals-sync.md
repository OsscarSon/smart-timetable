# v9.5.0 · Goals 跨设备同步（目标本体）

## 做了什么
- **目标（`goals-g:<id>`）现在跟着云同步走**（登录云同步后）：手机上创建的 SPM 目标，电脑上也能看到、编辑、删除。
- **只同步这一类键**。`goals-meta`（每台设备的 id）、`goals-links`（排程关联）、`goals-prefs`、`goals-plan-prefs` 仍然只在本机。
  - 改动：`js/hook.js`（目标键也通知同步）、`js/sync.js` 的 `syncKey()`。服务器 `user_data` 表不用改。

## 冲突怎么处理（不再弹“哪个版本”的对话框）
目标自带 `rev`（每次保存 +1，删除也算一次保存，所以删除的“墓碑”会赢）和 `updatedAt`：
- 两台设备都改过同一个目标 → **rev 大的赢；rev 相同则 updatedAt 较晚的赢**；输的一边会被覆盖。
- 改不同目标互不影响（每个目标一个键）。
- 其他数据的冲突提示照旧。

## 排程为什么只认“排程的那台设备”
课表（`mochi-wk:*`）本来就同步，所以 B 排的时段 A 也能看到；但 **`goals-links` 不同步**，A 不知道这些时段属于哪个目标。若 A 也去排，会重复。所以：
- 目标新增 `planDevice`：第一次提交排程时由那台设备认领（和日程写入放在同一个“全有或全无”的流程里）。
- 其他设备上：目标卡片显示“已在另一台设备上排程”；编辑页只读，没有排程 / 移除 / 跟随按钮；就算绕过界面调用 `commit()` 也会被拒绝（`errElsewhere`）。
- 逃生口：「在这台设备上接管排程」（有确认）。接管后另一台设备已排的时段不会被计入，可能重复——确认框里写明了。

## 已知限制
- 两台设备在同步之前各自提交了同一个目标的排程 → 日程按各自的周数据合并，可能出现重复时段；用「移除未到的时段」清理。
- 同一目标两边同时编辑，输的一边的修改会被覆盖（没有字段级合并）。
- 退出登录并“清除本机数据”时，`goals-*` 也会一并清掉。
- 完整的“任意设备都能管排程”（关联表按条合并）留给后续版本。
