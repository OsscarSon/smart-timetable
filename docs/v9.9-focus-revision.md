# v9.9 · Phase 3C Focus Revision

把设计包里的“Focus Revision”整合进 Study Space。**没有新增任何数据、存储键、云同步规则**；评分走的就是复习队列里三个表情按钮的同一条写入路径。

## 审计结论（动手前读过的代码）
- `js/srs.js`：`srsRate(t, g, D, today)`，`g` = 0 忘了 / 1 模糊 / 2 记得；结果写回 `t.iv / t.nx / t.fc`。设计稿的 Again / Okay / Got it 就是 0 / 1 / 2，没有发明新的评分数值。
- `js/study-space.js`：已有 `rate(idx,g)` = `srsRate(ST.topics[idx], g, dleft(subject), today()); sv(); rSt()`。Focus 直接复用同一组调用。
- `js/study-space-core.js`：纯函数聚合；章节“到期 / 新章节”的判断沿用它（不改）。
- `scripts/check.mjs` 对 study-space 的边界检查（无 `mochi-*` 字面量、只允许 `studyspace-prefs` 一个本机键、三语键一致、CSS 命名空间）全部继续通过。

## 行为
- 入口：Study Space 工作台的“Focus Revision”入口条（有数据时才出现；完全空数据仍是原来的空状态）。
- 队列：所选科目里“到期（due）”和“还没学过（fresh）”的章节，到期的在前；与复习队列里能评分的章节一致。未到期的章节不会被提前评分。每次最多 20 个，其余仍待复习。
- 选择页：用现有 `ST.subs` / `ST.topics`；无章节 / 全部已复习 → 空状态；只有 1 个科目 → 默认选中。
- 会话：一次一个章节，顶部进度条 + 可见的 Exit，三个评分按钮，Buddy 鼓励语；每次评分立刻写入并重新渲染。
- 总结：已复习 / Got it / 需练习 的数量；“再复习一轮”**只在还有剩余待复习章节时出现**（见下）；“返回学习”。
- 选择和进度只在内存（`S.f`）。离开页面 / 刷新即丢弃，已评分的章节在评分时已写入，不会丢。

## 和设计稿的有意差异
1. **“Review again”不是重新评同一批章节。** 评完后章节的下次复习日已在今天之后，若再评一遍会对同一章节重复计分、扭曲间隔。所以只有存在剩余待复习章节（例如超过 20 个封顶）时才显示，并开始剩下的那批；否则显示“你已经全部复习完了”。
2. **配色用主题变量，不写死设计稿的深棕色值。** 这样亮色 / 暗色 / 主题色都跟随；暗色下基本就是设计稿的配色。
3. 预览里的底部导航仅示意，没有使用；沿用 Mochi 原有底部导航。示例数据、示例评分、`alert()` 都没有带入。

## 安全措施
- 评分前按“下标 + 科目 + 章节名”重新定位章节；列表在会话中被别处改动（错位 / 被删）时，写到正确的章节，找不到就跳过且不写入，总结页会提示跳过数量。
- 防连点：新卡片出现后 0.3 秒内忽略评分，避免双击一次评两张。
- 键盘：科目开关切换后焦点保留；进入每个界面焦点落到标题；评分按钮是原生 `<button>`；遵守“减少动态效果”。
